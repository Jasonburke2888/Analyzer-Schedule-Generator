# V3 Database Schema

In-memory logical database for the Estimate Import / Resource Loading system. Plain JavaScript objects and arrays today; structured for future SQLite migration.

**Not connected to `js/app.js` (V2.8)** — schedule save/load, CSV export, and GitHub Pages are unchanged.

## End-to-end flow

```
Estimate Excel
    → Template Parser (app/estimate-import/)
    → ImportedEstimateRows
    → ActivityMappings (via EstimateDeliverables + ActivityLibrary)
    → ScheduleActivities
    → ResourceAssignments
    → P6 Export (future / existing CSV path)
```

```javascript
  format: "analyzer-schedule-v3-db",

  projects: [],
  estimateTemplates: [],
  disciplines: [],
  activityLibrary: [],
  estimateDeliverables: [],
  activityMappings: [],
  importedEstimateRows: [],
  scheduleActivities: [],
  resources: [],
  resourceAssignments: []
}
```

## Logical tables

| Collection | Purpose |
|------------|---------|
| **Projects** | Project header: `projectId`, name, client, FEL stage, PM |
| **EstimateTemplates** | Registered Excel/PSE parser metadata |
| **Disciplines** | Discipline list per project + lead |
| **ActivityLibrary** | Master/template activities for mapping targets |
| **EstimateDeliverables** | Deliverable lines derived from import rows |
| **ActivityMappings** | Links estimate deliverables → activity library |
| **ImportedEstimateRows** | Normalized parser output (standard import shape) |
| **ScheduleActivities** | Generated schedule lines from mapped imports |
| **Resources** | People/roles for loading |
| **ResourceAssignments** | Hours/resources assigned to schedule activities |

## Record IDs

Internal string IDs (`proj_1`, `imp_2`, …) generated by `Schema.nextId()`. Business key for cross-table joins is `projectId` (e.g. `1517`).

## Helper functions

| Function | Description |
|----------|-------------|
| `createProject(input)` | Create project row; returns `{ store, project }` |
| `addImportedEstimateRows(store, projectDbId, rows)` | Insert import rows + estimate deliverables |
| `getUnmappedRows(store, projectDbId)` | Rows with `mappingStatus` unmapped/partial |
| `mapEstimateDeliverableToActivity(store, input)` | Create ActivityMapping; mark row mapped |
| `generateScheduleActivitiesFromImportedRows(store, projectDbId)` | Build ScheduleActivities from mapped imports |

Aliases exist on `AnalyzerSchedule.Database` directly (same functions).

## Example (browser console)

```javascript
var db = AnalyzerSchedule.Database;
var store = db.getStore();
db.seedEstimateTemplates(store);

var { project } = db.createProject({
  projectId: '1517',
  name: 'Demo Project',
  client: 'Acme',
  felStage: 'FEL-3',
}, store);

db.addImportedEstimateRows(store, project.id, [{
  projectId: '1517',
  sourceFile: 'pse.xlsx',
  templateName: 'eichleay-pse-old',
  discipline: 'Engineering',
  deliverable: 'PSE Line',
  activityName: 'Develop - PSE Line',
  totalHours: 40,
  mappingStatus: 'unmapped',
}]);

var unmapped = db.getUnmappedRows(store, project.id);
```

## SQLite migration (future)

Each collection maps to a table with the same fields. `_meta.nextId` becomes auto-increment or UUID. `projectId` remains the foreign key for project-scoped rows.
